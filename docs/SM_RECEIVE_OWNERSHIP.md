# SM 周期收包所有权与发送节拍

## 适用范围

SM 约束适用于 `dc_assign_activate == 0` 的合并域交换；DC 分离读写约束见末节。
变更不调整 PDO 协议、CAN 帧顺序、固件过期命令策略或 CRC 默认配置。

## 运行约束

1. 进入 OP 后，每次发送记录尚未收齐的域。在所有域获得完整 WKC 前，不再次
   queue/send 同一域，避免 IgH 将仍在途的 datagram 重新置为 QUEUED，导致旧返回
   报文不能匹配，或过程映像被新输出覆盖。
2. 首次 receive/process 未收齐时，仅追加 receive/process。预算为半个应用周期，
   上限 100 μs，最多 128 次；不在补收期间发送、重发或多次解码同一 PDO。
   预算控制调用之间是否继续补收，不是 Linux 调度或单次 ioctl 的硬实时上限。
3. 公共 IgH API 无法可靠区分“仍在途”和“已返回但零/部分 WKC”。因此完整 WKC
   才释放域所有权；预算内未完成时返回 `IGH_ECAN_TIMEOUT` 并停止后续输出。
   诊断复位不解除停止状态，应用需结束会话、核查链路并重新初始化。该策略优先
   防止旧运动命令重发，不承诺链路异常时无中断运行。
4. SM 正常发送采用绝对期限，不累加普通 ioctl 耗时。发送调用耗时超过周期的
   1/8 时，下一期限退让到调用完成后一个完整周期，并记录重定位，不追赶积欠的
   周期。普通抖动仍存在；该软件保护不承诺物理相邻帧精确相隔 250 μs，必须抓包验证。
5. 迟到发生在 begin 之前时尚未生成命令，适配器重定位到新的安全期限并保留
   迟到统计。运行中已生成的命令若在排队前超过发送期限的 1/8，返回 `IGH_ECAN_TIMEOUT`
   并锁存 `sm_receive_fault=2`，不把该命令留到下一周期发送。启动 OP 等待不套用
   应用命令期限。进入内核后的延迟无法通过该检查撤回，仍需发送完成时间退让及固件保护。
6. 本次 `cycle_end_checked` 发出一次 LRW 后，进行有界 receive/process 回收。
   只有完整 WKC 才更新 shadow；不增加第二个 EtherCAT 读取报文。成功 end 后输入
   可用，下一 begin 不再次接收同一代。原先在 begin 解析的应用仍可读取上次 end 的 shadow。
   接收失败保留旧 shadow，但错误返回后不得将它当作当前有效输入继续控制。

应用应使用 `igh_mcan_port_cycle_begin_checked()` 和
`igh_mcan_port_cycle_end_checked()`。任一失败均须终止当前发送流程，不把仅写入
PDO writer 的数据当作已发送。旧 void 包装函数保留源兼容，但不能提供错误处理。

## 诊断字段

| 字段 | 含义 |
| --- | --- |
| `sm_late_receive_recovered` | 首次处理未收齐，追加接收后取得完整 WKC 的调用次数；不是漏帧数 |
| `sm_receive_timeouts` | 追加接收预算耗尽，触发停止输出的次数 |
| `sm_pacing_waits` | 为避免相邻发送间隔压缩而等待的次数 |
| `sm_pacing_wait_max_ns` | 上述等待的最大请求时长，单位 ns；不是实测线缆间隔 |
| `sm_receive_poll_calls` | SM receive 调用总数，包括补收调用 |
| `sm_receive_waits` | 提前进入接收时等待至上次发送完成后四分之一周期的次数 |
| `sm_receive_wait_max_ns` | 上述等待的最大请求时长，单位 ns |

`ecan_igh_reset_runtime_diagnostics()` 清零这些统计，不清除在途域、停止状态或上次
发送时间。结构体新增字段后应重新编译使用适配层的应用，不混用旧 ABI 二进制。

## 固件配套行为

SSC 尾部发现新的 SM2 事件时保留事件，不再只读取首尾确认。下一次中断执行正常
映射。`CycleExceededCounter` 仍记录周期超限，但不表示已丢弃命令。此机制不是
无限命令队列；持续输入超过处理能力时仍可能出现 ESC/MCAN 过载。

验收需同时检查：逐帧 ID 与载荷、缺帧/重复/乱序、WKC、发送间隔、截止时间、停止
恢复行为。数据帧全收齐但时序超限的测试只能判定完整性通过，不能判定实时性通过。

## 接收等待与计时口径

SM 接收在本包发送完成后至少等待四分之一配置周期，迟到进入时不再等待，以减少
返回包尚未到达时的重复 ioctl。该等待不会产生新的 EtherCAT 读取报文，也不改变
从站打包点。等待不计入 `receive_process_max_ns`，但计入应用周期执行时间；因此
不能仅凭 receive/process 数值下降推导端到端延迟改善。

已建立下一发送期限时，SM补收以该期限之前四分之一周期为截止点，最多追加512次
receive/process；没有有效发送期限时使用原有短预算。250µs周期也适用同一交付边界，
不在固定100µs追加轮询预算结束时提前放弃第二个以太网帧。该次数与时间均为继续调用的
上限，不保证单次内核调用或调度不会越过截止点；实际超周期仍必须记录并判定。
三台各双向256B的过程数据已经超过单个标准以太网帧可用容量，必须验收多帧回收及节拍，
不能由单站或256/256/128B组合的测试直接推定稳定。

完整回收后，end 在下一发送期限之前四分之一周期交付输入（正常 250 μs 配置下，
相对于本次发送期限为 187.5 μs），为下一批生成预留时间。接收提前完成时等待该点，
迟到不倒退时钟或清零超周期统计。`ecan_igh_collects_at_cycle_end()` 对 SM 返回真。
此变化改变输入解析所在的应用周期；N+k 必须结合主机抓包 RTT 解读，不能仅凭
周期编号减少宣称物理 CAN 往返更快。

适配器是 SM 唯一节拍所有者。stress 和 250 μs pipeline 不再叠加外层周期等待。
显式 `cycle_repeat_output` API 仍为兼容用途保留，不是运动控制的迟到补发方案；
调度器不调用该接口追赶。

SM同轮追加接收时，只对`sm_pending_mask`中仍未完成的域调用`domain_process`。
首次接收仍处理全部活动域；已完整回收且没有重新排队的域保持当前代次，最终WKC
汇总仍覆盖全部域。该优化减少重复ioctl，不跳过未完成域、不改变截止点，也不保证
单次内核调用不会超过实时预算。DC正常分离读写流程不因此改变。

## DC 分离读写的在途保护

每周期仍只发送一组 LWR 和一组 LRD。LWR 必须在发出 LRD 前取得完整 WKC，LRD
必须在复制输入映像前取得完整 WKC。未收齐时只追加 receive/process，不重新发送、
排队或解码。每次补收最多 128 次、时间预算最多 100 μs；LWR 的预算还受读取相位至
收集相位中点约束，LRD 的预算受本周期结束约束。预算是继续调用的边界，不保证单次
ioctl 或线程调度不会超时。

读取相位已延误至收集相位时不再发出 LRD。任何方向未收齐或相位等待失败均锁存停止
状态，后续 checked API 不再输出。已有完整输入映像不会被不完整的新映像覆盖。
`dc_receive_fault` 的 1/2 分别表示输出/输入方向失败，3 表示相位流程中断。
诊断复位不清除锁存状态，必须退出会话后重新初始化。

`dc_late_receive_recovered` 统计首次处理不完整、追加接收成功的次数；
`dc_receive_timeouts` 统计方向补收失败或错过读取发送截止点的次数。这些字段不等于
CAN 缺帧计数。完整 WKC 只证明 EtherCAT 数据报处理正常，不证明 CAN 命令在 Sync0
前准备完成，也不证明所有应答赶上 Sync1。
