# 主站兼容性与验收边界

## 默认部署

本示例默认使用标准 IgH/EtherLab 主站、标准 generic 驱动及公开的 `ecrt_*` 接口。
示例包不包含主站补丁、定制内核模块或自动修改主站源码的脚本。
CPU/IRQ 绑定、实时优先级及网卡设置属于运行环境配置，不改变设备协议。

默认选用标准主站不等于所有主站版本、同步模式和负载均已通过验收。
部署记录应包含主站源码提交、内核版本、加载模块身份、网卡驱动、固件版本、
PDO 大小、同步参数和测试负载。`ethercat version` 的版本字符串不能替代完整身份记录。

## 已知版本边界

以下问题在 IgH 1.6.9 源码提交 `b709e58147e65b5e3251b45f48c01ef33cc7366f`
的对照中出现。未验证其他提交是否包含相应修复，不按版本号推定其已解决。

| 场景 | 边界及处理要求 |
| --- | --- |
| 单方向 PDO ≤1392 B | 当前产品不依赖超大单 FMMU 分段。双向或多从站总量较大时允许标准主站拆成多个报文；仍需验证实时性 |
| 同周期 Sync0＋Sync1 | 启动对齐可能使实际相位偏离配置。必须通过 `[DC-PHASE]` 检查；出现 `MISMATCH` 时不得发送业务 CAN 命令，应更换经验证的主站版本或显式重新配置其他同步模式 |
| DC参考时钟尚未收敛 | `[DC-PHASE] verified`只核对ESC起点、周期和相位寄存器，不证明参考时钟已与主站时间收敛。OP/WKC及固定次数空PDO预热同样不能单独证明时钟收敛。首次发送运动命令前应核对实际参考时钟偏差，并为Sync0准备截止保留余量；尚未收敛时继续有界预热或明确退出 |
| 后台字典查询与外部 SDO 并发 | 可能出现字典不完整和后台 CoE 超时，即使外部 SDO 均成功。应验证冷启动、重扫后的字典完整性和并发事务；启动阶段串行配置只能降低触发机会，不能证明竞争已修复 |
| 冷字典查询期间请求 PREOP | 主站全局字典 FSM 可能延迟其他从站的状态切换。单从站空 PDO 对照中，后台查询另一从站字典时，PREOP 请求超过 2 秒仍未完成；字典完成后的对照约 17 ms 完成。该数据仅适用于所测版本和台架，不是通用停机上限。必须同时覆盖冷字典和暖字典，不以预热替代缺陷修复 |
| OP→Idle 退出 | 可能出现 `Datagram initialized`、`SKIPPED`。应用延时不能保证主站 FSM 交接正确，应核对主站修复及重复启停结果 |
| DC 周期先停止、从站仍为 OP | 可能触发同步错误 0x001A。应用应设计状态切换与周期停止的顺序；当前 close 中最后一次收包不等于完整的无告警停机握手 |
| 定制 generic / direct_xmit | 不属于本包默认环境，其抓包、队列与重试行为不得套用标准 generic 的结论 |

出现这些问题时，应向主站维护方提供源码身份、最小复现、内核日志和报文记录。
不通过修改固件 DC 起点、关闭 SDO Info、忽略 WKC 或放宽同步保护规避问题。
本文件不承诺任意未经验证的主站升级可以解决上述问题。

正常停机应持续检查实际 AL 状态；发出状态请求或命令行返回成功，不等于从站已经到达
PREOP。超出应用停机期限时应显式报告失败，并按设备安全策略处理。测试中的空 PDO
用于避免追加 CAN 命令，不能代替电机停机、安全转矩关闭或急停措施。

## 看门狗与配置结果判定

`0x001B` 表示 SyncManager 过程数据看门狗超时，不应与 `0x001A` 同步错误混用。
检查 ESC `0x0400` 分频值、`0x0420` 过程数据超时值、SM2看门狗使能及实际PDO写入间隔。
超时按 `(分频值+2)×计数值×40ns` 计算；例如2498和1000对应100ms。
业务周期不能等于超时上限，还必须容纳启动阶段的间隔变化、唤醒迟到及调度抖动。
短测偶尔通过不表示有足够余量，不应通过关闭看门狗使测试通过。

CoE写入返回I/O错误或超时，不保证从站未执行该写入。后台SDO Info与外部SDO竞争时，
从站的成功应答可能已经返回主站网卡，但未被正确交付给请求者。应保存抓包并核对目标值、
ApplyStatus和Active配置；复位、持久化、清零等有副作用命令不得盲目重试。
等待字典查询完成后串行配置只能作为诊断对照，不能替代主站邮箱所有权缺陷的修复。

只读SDO同样需要验证应答新鲜性。请求超时后立即重读同一index/subindex时，数值正确和
对象匹配不能单独证明应答属于新请求；上一笔已发布但尚未取走的应答可能具有相同内容。
恢复验收应核对原请求、残留应答消费、新请求及其应答的实际顺序。发送前清理已发布残留，
并不保证能够隔离在清理完成之后才产生的任意异步旧应答，二者需要分别验证。

邮箱互斥与快速响应是不同的验收项。主站应串行处理同一从站的邮箱事务，同时检查完整
字典、外部SDO返回结果及最长等待时间；仅统计外部SDO成功率不足以确认字典完整。
采用整个字典查询期间独占邮箱的实现时，外部请求可能等待查询结束。因此，同步SDO
读写不得放入SM/DC实时周期线程，尤其不能用于每周期发送运动命令。具体等待上限由
主站版本、字典规模和负载共同决定，不以单次台架测量作为产品时限保证。
邮箱所有权修复也不替代OP→Idle事务交接与DC停机状态切换的独立验证。

## 正常停止的判定

现有`ecan_igh_close()`负责资源释放，不是已完成验证的有界PREOP停机接口。
正常停止应先禁止新业务提交，在应用仍拥有主站期间维持有效空PDO及必要的DC同步，
请求PREOP，并确认从站实际状态及错误标志后再停止通信和释放资源。请求提交成功、
CLI返回成功或close返回成功，均不能替代实际状态确认。

`igh_mcan_stop_prepare()`/`igh_mcan_stop_poll()`将上述确认过程与资源释放分开。
管理侧负责异步提交PREOP，库只通过标准IgH接口维护空PDO、检查实际状态和域所有权；
不会隐式执行CLI、直接写AL Control或更改固件保护条件。接管后普通周期、重复输出和
启动轮询均不能再次发送业务。用法及失败终态见[API停机事务](../API.md#111-有界停机事务)。
新增接口不改变旧`close()`行为；`mcan_rx_dump`正常结束接入示例层标准CLI管理，
其他示例的业务停止策略未自动替换。CLI提交成功仍须由库确认实际PREOP；
冷字典竞争、多站同时业务、链路故障、在途取消及各客户应用仍须独立验收。

示例管理轮询固定为100 μs，不按SM短周期继续细分。管理子进程不继承FIFO优先级，
但仍继承CPU亲和性；周期线程必须留出实际调度余量。若查询开销占满同一CPU，管理
进程可能尚未完成程序加载便达到停止期限。此类失败与主站内部OP→Idle交接缺陷不同，
应分别核对进程调度、线侧状态请求及资源释放日志，不能通过忽略任一失败判定退出成功。

所测IgH 1.6.9配置状态机可能先进入INIT，再配置邮箱并进入PREOP。INIT属于EtherCAT
状态，不代表MCU复位；它只能作为中间状态，不能视为PREOP停机已完成。尚未回收的
datagram不能重复排队；只有确认从站已经离开OP后，才能将该domain记为状态切换退出。
切换前的WKC错误、切换期计数和业务期计数应分别保留，不得将全部WKC异常忽略。

正常停机接管前仍要求最后一个空PDO周期完整回收。接管后，分离LWR/LRD按域分别
确认：未确认输入不会阻断已确认的空输出，未确认输出不得改写或重新排队；
合并LRW仍按整个域确认。该策略只解除读写等待的耦合，不改变PREOP确认、
AL错误判定、WKC要求或故障返回。逐域服务不等于所有主机/并发邮箱场景已验收通过。

后台字典查询可能占用主站全局FSM，即使查询的是另一台从站，也可能推迟目标从站的
PREOP请求。OP→Idle交接补丁仅处理线程交接时已有事务的发送，不能使仍在OP线程中的
状态请求抢占字典查询。必须单独验证字典查询正在进行时的停机期限；等待字典预热、
延长测试超时或直接释放后能够恢复，都不能替代这一项。

还应单独记录“正常停止已确认PREOP”与“下一次启动无超时/迟到报文”两个结果。
前者通过不保证线程切换和在途事务已经全部收敛；业务期完整WKC及CAN零缺帧，也不能
抵消启动日志中的TIMED OUT或UNMATCHED。应按请求实际发出、应答到达和会话边界定位，
不能仅凭延迟打印的告警时间归因于当前业务周期。

空PDO停机验证不替代电机停止、STO、急停或其他系统安全措施。

## 验收顺序

1. 编译、扫描、设备身份及 SDO 读写；核对完整对象字典，而非只检查单项上传成功。
2. SM 基础收发；核对 PDO 长度、完整 WKC、CAN 字节、数量、重复和顺序。
3. DC 实际相位、参考时钟收敛与截止时间；三者分别检查后再增加 CAN 负载，不用 WKC 正常代替数据完整性。
4. 正常启停、重扫、链路故障及恢复；确认无旧运动命令重发。
5. 多从站满载、FoE 与长时间运行；分别记录条件，短测结果不得外推为满载保证。
