# DC 分相交换与同周期回收

本文描述可选的主站调度接口，不改变默认 Profile、PDO 协议、固件 Sync0/Sync1 行为或旧命令保护。使用 Sync01 前须确认目标固件支持该调度方式；不能仅根据固件支持 V2 包头推断支持 Sync01。新增配置字段后，应用与适配库须使用同一版头文件重新编译。

## 传输与回收

| 配置 | 主站输出/输入数据报 | 排队和发送 | 应用输入更新 |
| --- | --- | --- | --- |
| 原 STANDARD 模式 | LRW | 原流程 | 后续 `cycle_begin` |
| `enable_dc_combined` | LRW | 一次 master send | 当前 `cycle_end_checked` 成功后 |
| 分相接口，`rx_phase < tx_phase` | LWR / LRD | 两个时刻分别发送 | 当前 `cycle_end_checked` 成功后 |
| 分相接口，`rx_phase == tx_phase` | LWR + LRD | 两方向同时排队，一次 master send | 当前 `cycle_end_checked` 成功后 |

一次 master send 不等于任意 PDO 大小均能放入一个以太网帧；IgH 仍受 MTU 和数据报长度限制。单从站双向各 640 B 的台架抓包确认，同步排队的 LWR 640 B 与 LRD 640 B 位于同一以太网帧。单个 LRW 则包含 1280 B 非重叠逻辑过程映像。

`cycle_end` 的本周期回收是接收已发出的 EtherCAT 回程报文，不是再向从站发一次读取。它也不表示本周期 CAN 请求已完成应答。若输入在本周期 Sync1 发布，而主站读发生在 Sync1 前，该输入仍需下周期读取；应用应按批次号计算 N+k，不得人为扣减周期。

## API 配置

以下仅为传输层配置片段。仍须配置正确的从站身份、PDO 容量和 MCAN 通道。所有返回值均须检查。

```c
/* cfg 已完成基础配置，周期为 1000 us。
 * 同时排队 LWR/LRD；同周期 400 us 回收。
 * 分离发送时将第二个 0 改为晚于输出的读取相位，例如 200。
 */
if (ecan_igh_config_enable_dc_phased_cycle(&cfg, 300, 0, 0, 400) != IGH_ECAN_OK)
    return ERROR;
/* 分相配置函数先设置 Sync0；随后显式开启 Sync1。 */
if (ecan_igh_config_enable_dc_sync01(&cfg, 1000, 300, 950) != IGH_ECAN_OK)
    return ERROR;
cfg.dc_prepare_ahead_us = 100;
cfg.dc_min_prepare_us = 200;
```

使用 LRW 同周期回收时，保留 Sync01 配置，调用
`ecan_igh_config_enable_dc_combined(&cfg, send_phase_us, collect_phase_us)`。
该函数不修改已设定的 DC 时钟参数。分相要求
`rx_phase <= tx_phase < collect_phase < cycle`；LRW 要求
`send_phase < collect_phase < cycle`。

周期调用顺序为：`cycle_begin_checked` → 构建输出 → `cycle_end_checked` → 解析新输入。
`ecan_igh_collects_at_cycle_end()` 用于选择解析时机。上一代输入已在 end 回收后，下一次 begin 不重复执行接收和处理。begin/end 配对、错误返回、互斥与域所有权要求不变。

### 跨周期 Sync1 与仅 Sync0

Sync01 接口的两个相位都属于 `[0,T)`，不允许相同。`Sync1 < Sync0` 时，
相对间隔为 `T-Sync0+Sync1`，发布发生于下一主站周期，仍每周期一对事件。
例如 T=1000 μs、Sync0=600 μs、Sync1=300 μs，间隔700 μs：
N/600发送CAN，N+1/300冻结并发布反馈。若主站N+1/200已读取，完整反馈等待N+2读取。
这里只改变相位计算和读回校验，不取消 WKC、截止、旧命令或所有权检查。

```c
/* 写0 us，读200 us，400 us内完成回程确认。检查各调用返回值。 */
if (ecan_igh_config_enable_dc_phased_cycle(&cfg, 600, 0, 200, 400) != IGH_ECAN_OK)
    return ERROR;
if (ecan_igh_config_enable_dc_sync01(&cfg, 1000, 600, 300) != IGH_ECAN_OK)
    return ERROR;
```

仅Sync0模式省略第二个调用；若从Sync01配置切换，显式调用
`ecan_igh_config_enable_dc_sync0(&cfg, 1000, 600)`，清除Sync1配置。
固件在Sync0提交输出并执行输入映射，因此本次命令的异步CAN应答通常等待后续Sync0发布。
该模式不承诺N+1；必须继续检查完整性、顺序和实际落点。它不同于“已启用Sync1但信号丢失”，
后者仍按同步故障处理，不自动切换发布事件。

跨周期与仅Sync0属于独立验收条件；不得用其他相位或启用Sync1的结果代替。

### 应用消费与 N+k 统计（解析时刻）

`igh_mcan_port_receive()` 解析最近一次成功回收的输入映像，不自行发送 EtherCAT
读取报文。使用 end 回收模式时，仅在下一次 begin 后调用该函数，会使应用晚一个
周期使用已经可用的应答。应根据 `ecan_igh_collects_at_cycle_end(&ec)` 选择消费点：

| 回收方式 | 解析调用位置 | 周期编号的含义 |
| --- | --- | --- |
| begin 回收 | begin 成功后 | 该 begin 所属的应用周期 |
| end 回收 | end 成功后立即调用 receive | 该 end 所属的应用周期，不等到下一次 begin |

begin/end 的任一步失败时，必须进入既有故障停止流程；不得解析未确认的新输入或
继续推进控制目标。主站应分别记录“发送命令周期”“EtherCAT 输入回程周期”和
“应用消费周期”。原有日志如果确实在 N+2 才消费，应保留 N+2 记录，不能通过
修改统计偏移将其称为 N+1；应修改调用顺序并重新测试。

例如，1 ms 周期中在 N 周期写入，N+1 周期 200 μs 相位读取，可在 N+1 的
end 成功后消费。即使全部应答为 N+1，从写入到返回也可能超过 1 ms。
该例说明时间点关系，不保证 CAN 对端能赶上相应的 Sync1 发布截止。

## 准备余量与错误处理

| 字段/诊断 | 含义 |
| --- | --- |
| `dc_prepare_ahead_us`，默认 0 | 允许周期调度器在下一个网格边界前准备命令。压测程序会提前唤醒；自定义应用须自行按相同绝对网格调度。不会自动提前线上发送相位。 |
| `dc_min_prepare_us`，默认 0 | 非零时，在 PDO 排队前检查主站估算的 Sync0 剩余时间；预算不足则失败停止，不排队或跨周期重试该命令。 |
| `dc_prepare_samples` | 业务周期发送准入检查次数，不包含等待 OP 的初始化探测。 |
| `dc_prepare_slack_min_ns` / 日志 `host_slack_min_ns` | 排队前主站时间到预定 Sync0 的最小估算差值，允许为负；不是固件 READY 余量。 |
| `dc_send_deadline_misses` / `deadline_misses` | 发送准入失败次数；不得计为成功周期。 |
| `dc_receive_fault=4` | 发送准入失败的会话锁存状态。沿用该字段承载会话失败，不代表发生了接收 WKC 错误。 |

提前准备必须小于 `cycle - collect_phase`。准备预算必须不超过计划发送相位至 Sync0 的间隔。预算须覆盖排队、驱动/NIC、线上传输及固件读取、校验、预装成本，并由目标系统实测确定。上例 300/950 μs 与 200 μs 预算是单台 640 B 台架对照参数，不是所有设备的默认值或实时性保证。

主站检查无法预知检查之后发生的内核、NIC 或固件长尾。固件代次、过期命令、MCAN 槽位所有权和取消保护必须保留。WKC 完整仅证明 EtherCAT 数据访问成功，不能证明命令已从 CAN 发出。验收还应核对发送批次、实际应答及固件丢弃计数。

输出确认超窗时，即使该次LWR的WKC完整，也必须按失败处理。此时该命令可能已经
进入从站或CAN总线，不得自动重发原正文；故障退出只在输出域所有权确认后构建新
序号空包。排队前准入失败与已发出后的确认失败，应分别记录，不能都解释成“未发送”。

`receive_process_max_ns` 是主站接收处理段的墙钟耗时峰值，包含调度阻塞。输出确认
失败会直接返回，因此其耗时也须计入峰值；事件记录中的 `recv_ns` 可用于核对该次
故障。它不是MCU的ESC读取时间、CAN处理耗时或物理Sync0准备余量。早期适配库存在
输出确认失败未更新该峰值的问题；核对历史日志时不能仅据汇总最大值排除长尾。

### 周期线程唤醒与命令提前准备的区别

接收示例 `mcan_rx_dump` 的 `--spin-us` 默认值为 0，此时线程睡眠至计划周期边界，
实际进入周期函数仍可能晚于该边界。该参数设为非零时，先提前结束睡眠，再在末段等待
原定边界，不改变 Sync0/Sync1、PDO 发送相位或回收截止。内部等待段最多为半个周期。
它与 `dc_prepare_ahead_us` 不同：后者允许应用在下一周期边界前准备命令。

需要较小发送抖动时，可在专用实时线程上对照测试 `--spin-us 100`，同时记录 CPU 占用、
实际唤醒迟到、排队耗时、send 调用时间和回包确认余量；该数值不是通用保证或内核修复。
CPU/IRQ 亲和性、线程优先级及网卡配置应保持可追溯，测试报告须区分带记录器与不带记录器。
不得用扩大回收截止、忽略 WKC 或跨周期补发旧命令替代调度验证。

准备窗口还应计入线上字节的串行传输时间。在 100 Mbit/s 链路上，仅 1280 B 数据区的
串行传输即为 102.4 μs，640 B 为 51.2 μs；这些数值尚未包含 Ethernet/EtherCAT 开销、
主站排队和从站处理时间。双向各 640 B 的合并 LRW 与分开发送的 640 B LWR 具有不同的
时间预算，不能直接沿用相同的最早 Sync0 参数。该计算也不能代替 SM2 事件和固件 READY
实测：ESC 在何时形成可消费映像、Sync0 中断在何时得到服务，仍须单独核对。

`host_slack_min_ns` 为正只表示主站排队前尚有估算时间，不表示线上报文已到达或固件已
准备完成。N+1 是周期编号差；例如主站在下一周期较晚相位读取时，全部 N+1 仍可能对应
大于 1 ms 的实际往返时间。

接收侧只在全部相关 domain 的 WKC 完整且未超过回收期限时更新输入并释放所有权。同帧 LWR/LRD 分别检查两方向；不能用单方向成功替代全部成功。短时补收仅调用 receive/process，不重新排队、不重复发送。超过预算或等待失败后锁存错误，应用必须停止推进运动目标；诊断统计清零不解除错误锁存或域所有权。

## 验收限制

合并与分离模式均须验证 WKC、请求和应答数量、逐字节内容、顺序、截止失败、排空结果及 N+k 分布。
已有对照出现 WKC 正常但 CAN 丢批，不能宣称八帧全 N+1 或将单次短测外推为发布资格。
用于测试的命令行选项由具体应用提供；本文的配置以公开 API 为准。
