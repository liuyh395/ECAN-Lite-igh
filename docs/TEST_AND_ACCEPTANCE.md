# IgH 测试与验收

本文给出 ECAN-Lite IgH 示例包的通用测试顺序、实时性定义和结果记录格式。测试从最小
链路开始，上一层通过后再增加从站、通道、帧数和周期压力。

## 1. 测试顺序

| 步骤 | 目标 | 通过条件 |
| --- | --- | --- |
| 离线构建 | 确认编解码器、适配层和示例可构建 | CMake 配置、编译和主机测试返回 0 |
| EtherCAT 基础 | 确认 SDO、PDO、OP 和 WKC | 配置成功，预热后 WKC mismatch 为 0 |
| 单通道一帧 | 确认真实 CAN/CAN FD 双向链路 | ID、DLC、payload 和序号一致 |
| 全通道额定负载 | 验证公平性、队列和实时性 | 无丢帧、重复、乱序，延迟满足目标 |
| 过载与恢复 | 验证有界退化 | 错误可观测，降载后数据流自动恢复 |

空 PDO、未连接 CAN 对端或由主站伪造的回复不能代替真实 CAN 总线测试。没有物理回路时，
只能据此确认 EtherCAT 交换和 WKC，不能宣称 CAN 闭环通过。

## 2. 默认实时 profile

### SM 四相流水

- EtherCAT 子周期：250us；
- RxPDO 128B，TxPDO 256B；
- MCAN0、1、2、3 依次获得固定相位；
- 每个 MCAN 通道的业务控制周期为 1ms。

### DC 错周期闭环

- EtherCAT 周期：1ms；
- Sync0 shift：900us；
- RxPDO、TxPDO 均为 384B；
- 周期 N 下发请求，以 N+1 取得对应回复为目标，具体结果须按固件调度和负载实测。

周期、PDO、相位和交换策略属于同一个 profile。切换模式时使用适配层的 profile API，
不要只复制其中一个参数。CPU、实时优先级和网卡中断设置见
[CPU 与 IRQ 配置](CPU_AFFINITY.md)。

## 3. 实时性定义

主站在 EtherCAT 周期 `N` 的有效 RxPDO 中写入请求，对应 CAN 回复首次出现在 TxPDO 的
周期记为 `N+k`。报告必须说明 `k` 的基准，不把工具中的 `same_cycle`、队列深度或平均
周期直接等同于业务闭环延迟。

每项结果至少记录：

- 软件版本、示例名称和完整命令；
- 主站、内核、EtherCAT 接口类型和实时配置；
- 实际 CPU/IRQ 亲和性、优先级、`spin_us`、`dc_prepare_ahead_us` 及诊断记录器开关；
- 从站数、PDO 字节数、SM/DC、周期和 shift；
- CAN 类型、11/29 位 ID、仲裁/数据速率、BRS、payload 和物理连接；
- 通道数、每通道帧数、应答器类型、预热样本和正式样本；
- 已发、已收、丢失、重复、乱序和 payload 错误；
- WKC expected/actual、mismatch、AL 状态变化和 MCAN 错误计数；
- min/avg/p99/max 和各周期延迟桶。

### 证据完整性与结果分层

业务完整性、实时性、诊断完整性和启停恢复应分别给出结果。主站程序返回成功不能替代
应答器、抓包工具以及配置恢复工具的结果。应答器 trace 溢出不等于 CAN 业务丢帧，但该
轮不具备完整诊断证据；抓包丢失或未采集到有效输入 PDO 时，不得将“未发现错误”判为通过。

合并 LRW 和分离 LWR/LRD 均须解析输入 PDO 包头。吞吐率按本轮实际周期和有效业务区间
计算，不能将 SM 250 μs 的数据套用 1 ms 计算。短测完整不构成持续满载或最坏延迟保证。

DC 的 Sync0 相位不是从解包入口开始计算的处理预算。若 RxPDO 到达或开始处理时本次
Sync0 已经过期，不能通过删除旧命令保护、在新命令之后补发旧命令来满足数量验收。
应分别测量主站提交、EtherCAT 传输、ESC 读取、READY 和 Sync0 服务时刻，再评估交换方式
及发送/同步相位。输入发布相位相同不代表不同交换方式具有相同的命令准备余量。

主站时间分解至少区分周期边界至应用进入、命令准备、域排队、send 调用、网络接收交付及
逐域确认。平均周期接近目标值不能排除单周期迟到；带记录器的末尾窗口统计不能宣称为
全程最大值或无记录器的性能结果。`spin_us` 与命令提前准备的区别见
[DC 分相交换](DC_PHASED_EXCHANGE.md#周期线程唤醒与命令提前准备的区别)。

## 4. 过载与恢复

超过 PDO、软件队列或 CAN 带宽时允许按策略丢业务帧，但应满足：

- 周期线程和设备数据路径保持有界，不发生持续阻塞；
- 不出现设备循环复位、队列索引损坏或不可恢复的 EtherCAT 状态；
- 丢帧、压力和错误原因能从运行统计或 SDO 诊断中观察；
- 负载降回额定值后，OP/WKC 和数据流能够自动恢复；
- 恢复后不残留重复帧、半帧或上一次会话的数据。

把该组合列为目标系统的稳定配置。
